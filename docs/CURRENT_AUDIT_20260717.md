# 地球：人类 当前复盘与下一阶段执行计划

日期：2026-07-18
目标平台：Minecraft 26.2 / NeoForge 26.2.0.7-beta
当前工作树版本：0.1.16
当前 Git 基线：0.1.16（提交 `8fb3b15`，tag `earth-human-neoforge-26.2-v0.1.16`）

## 1. 审查边界与依据

本轮只规划 `地球：人类 / Earth Human`。相邻三个项目只用于核对联动契约，不在本轮修改：

- `Earth on Minecraft / 我的地球`：现实材料、地质、工业、能源与环境事实。
- `Earth Online: Magic`：魔法路线、以太场和魔法适应贡献。
- `地球 Online：玄幻`：修炼路线、灵气场和玄幻适应贡献。

本轮依据包括：

- 当前源码、资源、测试、构建产物和 26.2 实例日志。
- `docs/vanilla-mechanics-audit-roadmap.md`、`docs/compatibility.md` 和四项目联动契约。
- 其他窗口沉淀到 MC Skill v3.34 的规则，尤其是身体区域一一对应、背包快捷入口、手册保留、代码驱动预览、真实本地化文本和仓库边界。

固定产品边界：

1. 身体状态只保留头部、躯干、左臂、右臂、左腿、右腿六个区域，不继续细分器官或关节。
2. 原版生命、最大生命、护甲、治疗、复活和其他 Mod 的最终结算仍是默认兼容入口。
3. 真实内容可以深入，但默认交互必须让不了解技术的玩家看得懂、知道下一步怎么处理。
4. 不增加强制公共前置；联动优先使用公开 API、标签、数据契约和安全退化。

## 3. 当前主要风险

### P0：正确性与发布阻断

#### 3.1 命中左右映射已通过纯逻辑验证，事件级仍需扩展

`BodyHitResolver` 已接管局部左右和六部位选择，四个基准 yaw、头部、躯干、双臂和双腿测试均通过。剩余风险不再是基础坐标符号，而是复杂实体事件组合（护甲、吸收心、复活保护和其他 Mod 改伤害）尚未有事件级 GameTest。

#### 3.2 当前自动测试没有覆盖事件管线

现有测试覆盖数学迁移、兼容伤害比例、治疗溢出、活动采样和 API 参数解析，但没有覆盖：

- `LivingDamageEvent.Pre/Post` 与其他 Mod 修改伤害后的顺序。
- 原版治疗事件和直接 `setHealth` 的去重。
- 死亡克隆、最大生命变化、吸收心和复活保护组合。
- 伤害扩散跨过已经归零部位时是否继续到头部。

处理方式：先提取纯函数和状态转换，再做事件级 GameTest / 开发实例脚本，不直接把 1100 行事件类整体搬动。

#### 3.3 版本真值不一致

源码、README、metadata、Git 提交/tag/release 和构建目标已对齐到 0.1.16；剩余风险是客户端交互尚未由真实玩家复核，以及事件级复杂伤害组合尚未覆盖。

## 4. 下一阶段执行计划

### 阶段 A：0.1.16 正确性与界面闭环（已完成代码与专服验证）

目标：先完成用户已经明确要求但尚未真正实现的入口和视觉闭环。当前代码、资源校验、构建、部署和专服启动已完成；真实客户端点击和翻页仍需用户复核。

1. 新增纯逻辑 `BodyHitResolver`，修正左右侧算法并增加四朝向测试。
2. 按 26.2 patched sources 的实际事件签名，实现原版生存背包内的紧凑六部位摘要。
3. 摘要整体可点击，点击后打开身体状态界面；创造物品栏和不兼容的第三方容器不强行覆盖。
4. 保留 `野外健康记录`，改为五页说明型入门手册，并提供进入实时身体状态的按钮。
5. 身体页和背包摘要增加当前完整度、区域名称、悬浮说明、双语文本和左右视角一致的显示。
6. 使用 Image-2 生成并接入 `muscle_strain` 效果图标；身体示意图暂保持可读的代码绘制版本，避免把未审定的生成图当作最终 UI 资产。
7. 重写 UI 预览清单，使用真实背包摘要与状态页布局，不再用物品展示页冒充功能入口。

验收标准：

- 四个 yaw 朝向的左右命中测试全部通过。
- 320x240、426x240、854x480 三种逻辑尺寸预览无重叠或越界。
- 背包摘要六个区域与同步数据一一对应，点击可打开状态页，手册仍可独立发现。
- 19 项测试通过，并新增命中、区域、入口状态和资源完整性测试。
- 构建、部署和专服进入世界通过；真实客户端的打开背包、点击摘要、手册翻页、受伤和护理仍是下一次客户端验收项。

### 阶段 B：0.1.17 兼容接口与伤害语义

目标：让其他 Mod 能声明人体语义，而不是要求 Earth Human 猜测所有实现。

1. 保留 `EarthHumanApi v1` 全部方法，增量提供更详细的部位快照；破坏性改动才进入 v2。
2. 增加服务端权威 `applyActivity`，供自定义坐骑、飞行、法术动作和其他 Mod 健身动作申报距离、负荷和参与部位。
3. 建立数据驱动 `DamageProfile`：冲击、切割、穿刺、热、冷、窒息、毒性、魔法、全身和旁路。
4. 增加分配前/受伤后/治疗后的小型事件接口，并继续尊重原版最终伤害、护甲和其他 Mod 事件结果。
5. 护理扩展从固定五类标签升级为可注册护理描述，但保留现有标签作为无 Java 依赖的基础入口。
6. 把手臂、腿和躯干后果逐步改为 Earth Human 自己的功能修正，减少常驻 `Weakness`、`Slowness`、`Mining Fatigue` 与其他 Mod 效果冲突。

验收标准：API v1 调用方无需修改；缺少 Earth Human 时附属安全关闭；未知伤害走保守默认；整合包可仅用数据包覆盖常见伤害和护理类别。

### 阶段 C：0.2.0 环境、衣物与 PPE 闭环

目标：让现有体温、口罩、补给物和 Earth on Minecraft 环境接口真正产生互相解释的玩法。

1. 建立 `ThermalContext`：群系温度、昼夜、海拔、天气、水中/湿身、附近热源和维度共同决定缓慢温度变化。
2. 建立轻量衣物/PPE 描述：覆盖部位、保温、散热、重量、湿润和过滤；优先通过 item tags / 数据组件接入原版和第三方装备。
3. 默认不强制新增装备前置。先支持原版装备槽；可选 Curios/饰品栏通过独立适配器接入，缺少时安全退化。
4. 让布口罩、防尘口罩、保温毯、暖贴和降温包具有明确使用场景，而不是只有数值或配方。
5. 消费 Earth on Minecraft 已发布的 `water/potable`、`water/treated`、`environment/heat_sources` 和 `environment/air_pollution_sources` 角色接口；环境强度仍由数据或查询 API 提供，不能仅凭标签写死高伤害。

验收标准：单独安装 Earth Human 时使用原版环境形成闭环；安装 Earth on Minecraft 后只增加来源和环境事实；卸载本体后存档仍可加载。

### 阶段 D：0.2.x 疲劳、睡眠、医疗与动作深化

1. 把疲劳拆成即时疲劳、连续活动负荷和睡眠债，但界面仍给玩家一个主结论和清晰处理建议。
2. 建立真正的动作状态机：动作 ID、持续时间、参与部位、服务端判定、客户端表现和中断条件；器材不再只依赖原版吃/喝/拉弓动画。
3. 肌肉拉伤改为部位化状态，拉伸、休息、热敷和过度训练形成恢复闭环。
4. 医疗只扩展到常见外伤、消毒、包扎、夹板和康复；暂不进入完整器官、随机疾病和复杂营养素 UI。
5. 增加玩法级测试向量：连续走路与间歇休息、白天小睡、夜间跳时、受伤后继续使用、治疗优先级和死亡后长期状态。

### 阶段 E：四项目联动收口

Earth Human 本仓库负责：

1. 同时读取旧 `earth_online_arcana.*_bonus` 和未来按来源拆分的 contribution 键，迁移期保持兼容。
2. 增加“已安装联动”说明页，只显示当前实际可用的材料、环境和超凡适应效果。
3. 不直接写 Magic、玄幻或 Earth on Minecraft 的私有数据。

相邻仓库必须先完成：

1. Magic 与玄幻将共同写入的 `endurance_bonus`、`breath_capacity_bonus`、`body_tempering_bonus` 拆成按来源贡献。
2. 增加共享契约版本和幂等迁移；卸载、重装或只保留一个附属时不重复叠加也不清除兄弟数据。
3. Earth on Minecraft 后续提供有界缓存的环境/地质查询，而不是要求 Earth Human 高频扫描工业和地质方块。

最终验收使用四个 Mod 的 15 种非空安装组合做专服启动冒烟测试，并重点客户端验证单独安装、两两联动和四个同装。

## 5. 固定执行顺序

0.1.16 收尾按以下顺序完成；下一轮从阶段 B 的兼容接口开始，不再先扩展零散物品：

1. 复查 Git 工作树，只纳入源码、资源、文档和可复现预览工具，不纳入 `tmp/`、构建缓存、运行目录和生成源图。
2. 建立 0.1.16 提交、tag 和 GitHub 测试版 jar，远端下载后重新核对 SHA256。
3. 用户在目标客户端复核背包摘要、点击入口、手册翻页和双语显示。
4. 下一阶段先实现兼容 API 的活动申报和数据驱动伤害语义，再扩展环境、衣物和空气质量。

## 6. 暂不抢优先级的内容

- 更多身体部位、器官和骨骼细分。
- 完整营养素面板、食物腐败和随机疾病。
- 大量只增加物品数量但没有用途闭环的医疗或健身道具。
- 强制公共前置或把四本手册合并成一个必装核心。
- 在伤害、入口、版本和兼容契约未稳定前继续扩大跨 Mod 数值联动。
