# 地球：人类 / 原版 MC 机制对照规划

日期：2026-07-08
目标版本：MC 26.2 / NeoForge 26.2.0.7-beta
当前基线：v0.1.14

## 1. 总体判断

`地球：人类` 现在已经有了水分、体温、疲劳、部位血量、HUD、简单医疗、锻炼和床上休息，但这些系统还是“点状功能”，还没有完整覆盖原版 MC 的玩家生存闭环。

下一阶段不应该继续零散加物品，而应该对照原版机制逐个补齐：

- 原版已有的核心体验要保留：挖矿、战斗、探索、睡觉、吃东西、死亡复活、装备、附魔、药水、维度差异。
- `地球：人类` 负责把这些体验解释成人体状态，而不是把原版玩法完全打断。
- 复杂真实难度不要塞到默认模式，默认应是“能理解、能处理、能继续玩”。
- 所有新系统都需要玩家可见反馈：HUD、命令、物品 tooltip、手册页、必要时聊天提示。

## 2. 原版血量 / 伤害 / 死亡

### 设计定位：原版血量桥接层

身体部位系统不能简单理解成“把原版血量砍成 5 点头部血量”。更合理的边界是：

- **原版血量仍然是 Minecraft 生态兼容入口**：其他 mod 的治疗、护甲、属性、伤害减免、复活、职业、种族、装备词条，默认都通过原版生命值、伤害事件和属性系统工作。
- **红心条代表头部/意识安全，不代表全身总血量**：玩家看到的原版红心可以解释为“头部与立即致死风险”，但不应该让其他 mod 误以为玩家总生命只有头部那 5 点。
- **部位血量是扩展状态，不是替代全部原版机制**：躯干、手臂、腿部负责行动能力、持续伤害扩散、治疗优先级、疲劳/训练联动和 HUD 表达。
- **原版最终伤害结果应被尊重**：其他 mod 已经计算过的攻击力、护甲、抗性、难度倍率、附魔和事件修正，应该作为 `地球：人类` 的输入，而不是被本 mod 重新推翻。
- **只有明确需要人体解释的伤害才转入部位系统**：摔落、近战、远程、爆炸、火焰、窒息等可以按部位处理；虚空、管理员 kill、剧情/脚本强制死亡等应允许旁路。

建议实现成三层，而不是硬改一个属性：

1. **Vanilla Bridge / 原版桥接层**
   - 监听原版最终伤害和治疗结果。
   - 不默认长期压低 `MAX_HEALTH`，避免和生命上限类 mod 冲突。
   - 必要时只做可配置的“显示/同步策略”，例如把红心变化同步到头部状态，或把头部危险同步回原版死亡。
2. **Body State / 人体部位层**
   - 持久化头、躯干、双臂、双腿。
   - 根据原版最终伤害分配到部位。
   - 部位归零不一定死亡，但影响行动、挖掘、战斗、睡眠恢复和治疗提示。
3. **Compatibility API / 兼容接口层**
   - 提供 tags、事件或小 API，让其他 mod 可以声明“这个治疗物品治疗头部/躯干/肢体”“这个护甲覆盖哪些部位”“这个伤害应旁路/全身分摊/指定部位”。
   - 没有显式接入的 mod 走保守默认：尊重原版结果，只附加轻量人体解释，不破坏原玩法。

兼容优先级：

1. **不破坏原版和其他 mod 的基础可玩性**：治疗、复活、护甲、生命上限、伤害减免必须尽量保留。
2. **人体系统解释结果，而不是抢走全部控制权**：先读取最终结果，再分配/记录/提示。
3. **玩家默认不需要理解兼容细节**：HUD、手册和命令只说“红心代表头部危险，全身状态看小人/手册”，不要暴露事件管线术语。
4. **整合包作者可以调参或关闭模块**：身体血量、红心桥接、伤害分配、治疗联动都要可配置。

### 当前状态

- 已有头、躯干、双臂、双腿血量。
- 默认 `vanilla_compatible` 保留原版红心作为生态兼容入口，并把吸收后真实伤害映射到部位；可选 `head_bar` 才把红心条作为头部风险显示。
- 默认模式仍由原版生命归零负责死亡；`head_bar` 模式下头部状态会同步回原版生命。躯干/四肢归零产生功能惩罚。
- 复活不再重置全身，只给头部最低苏醒值。
- 已加入 `casual`、`standard`、`realistic`、`custom` 预设、系统开关、倍率和复活最低稳定比例。
- 已加入 `bypasses_body`、`head_priority`、`full_body` 伤害类型扩展标签。

### 主要缺口

- 缺少伤害类型矩阵：摔落、近战、远程、爆炸、火焰、窒息、溺水、中毒、凋零、魔法、饥饿、虚空等应分别落到不同人体系统。
- 当前大部分非头部伤害被简化为随机或近似部位，缺少“伤害来源 -> 部位/系统”的统一表。
- 没有明确区分外伤、内伤、热伤、冻伤、窒息、毒性、疾病风险。
- 死亡后的长期后果还很粗：只保留身体状态，没有恢复/昏迷/虚弱期。
- `head_bar` 仍会接管非头部伤害，属于明确的低兼容沉浸模式；默认模式已经不再归零原版最终伤害。
- 当前“原版血量 -> 头部血量”的同步还不够精细：治疗、再生、吸收生命、额外最大生命、临时生命、复活保护等都需要明确规则。
- 缺少对外兼容接口：其他 mod 暂时无法声明治疗部位、护甲覆盖、伤害性质或旁路规则。

### 规划

1. 建立 `DamageProfile` 表，把原版 `DamageSource` 映射为：
   - 主要部位：头/躯干/四肢/全身。
   - 伤害性质：冲击、切割、穿刺、热、冷、窒息、毒性、魔法、环境。
   - 是否允许旁路部位系统：虚空、管理员 kill 等。
2. 近战和远程优先用命中方向、视线高度、距离、实体位置估算部位。
3. 投掷物比近战更应该确定：优先用投掷物实体位置/速度线段裁剪玩家碰撞箱，得到命中高度和左右侧，再映射头、躯干、手臂、腿。
4. 爆炸使用爆心到玩家碰撞箱最近点估算主要冲击部位；近距离爆炸偏躯干/全身，低位爆炸偏腿，高位爆炸偏头/上身。
5. 火焰/岩浆按接触高度和范围处理：脚下一格火、热地面、仙人掌/浆果等低位接触优先腿部；全身浸入岩浆或持续燃烧才偏躯干/全身压力。
6. 火焰/岩浆还应叠加体温压力，不应只套原版着火逻辑。
7. 毒/凋零/饥饿保留原版威胁，但同步到人体状态：中毒、营养/水分压力、全身虚弱。
8. 死亡复活后进入短暂“恢复期”自定义状态，降低效率但不反复洗血。
9. 继续完善已经加入的 `HealthBridgeMode` 配置：
   - `vanilla_compatible`：默认模式，不压低最大生命；红心仍由原版和其他 mod 控制，人体系统把红心解释为头部风险并显示额外 HUD。
   - `head_bar`：沉浸模式，红心只显示头部，但生命上限修饰必须可配置、可关闭，并尽量只使用本 mod 自己的稳定 modifier。
   - `body_only_overlay`：兼容优先模式，不改原版血量，只在 HUD/命令/手册显示身体状态。
10. 增加治疗桥接：
   - 原版普通治疗优先恢复头部或最危险部位，具体由配置决定。
   - 其他 mod 增加最大生命时，按原版最大生命比例扩展各部位容量，而不是只让红心变长。
   - 自定义绷带/急救包/夹板明确治疗部位。
   - 其他 mod 治疗默认保留原版效果，同时按治疗量的一部分映射到部位，避免“红心满了但身体永远黑”的割裂。
11. 增加护甲/覆盖桥接：
   - 先读取原版最终减伤结果，不重新实现护甲公式。
   - 用 tags 或可选 API 标注护甲覆盖部位、重量、保温/散热。
   - 没标注的护甲只作为原版减伤，不额外惩罚。
12. 增加外部兼容入口：
   - `earth_human:body_healing_items/<part>` 标签：声明治疗目标。
   - `earth_human:damage_bypass_body` / `damage_full_body` / `damage_head_priority` 等伤害标签或映射表。
   - 公开轻量事件：伤害分配前、部位受伤后、部位治疗后，让附属或整合包能接入。

## 3. 饥饿 / 饱和度 / 食物

### 当前状态

- 主要接入水分和部分补给物。
- 没有真正改造原版饥饿、饱和度、食物营养。

### 主要缺口

- 原版食物只处理饥饿和饱和，`地球：人类` 还没有读取食物类型。
- 能量棒、葡萄糖凝胶等现在直接减疲劳，缺少“热量/糖分/恢复窗口”的解释。
- 饮水恢复和吃食物恢复是两条割裂路线。
- 没有“吃太少/长期奔跑/睡眠不足”的协同。

### 规划

1. 保留原版饥饿条，不接管基础吃饭体验。
2. 增加轻量营养标签：
   - `earth_human:hydrating_foods`
   - `earth_human:quick_energy_foods`
   - `earth_human:slow_energy_foods`
   - `earth_human:warm_foods`
   - `earth_human:cold_foods`
3. 食物吃完时按标签影响水分、体温、疲劳恢复效率。
4. 不做复杂三大营养素 UI，除非进入未来“地球人类硬核/营养附加包”。
5. 新手提示：疲劳高时告诉玩家“休息、睡觉、补水、吃能量食物”的优先级。

## 4. 水分 / 饮水 / 环境消耗

### 当前状态

- 水分随时间、移动、奔跑、下界降低。
- 水瓶、牛奶、蜂蜜瓶、汤类和自定义饮品可恢复。

### 主要缺口

- 没有区分水源：水瓶、河水、海水、雨水、药水、汤。
- 没有水质系统，也没有地球 Online 的水处理联动。
- 下界热环境只增加消耗，没有与体温和疲劳形成完整压力闭环。

### 规划

1. 短期保留“安全饮水”简化，不默认惩罚玩家喝水。
2. 加入水源标签和基础水质：
   - 安全水：净水、装满水壶、补水饮料。
   - 可疑水：普通水瓶、雨水收集。
   - 特殊液体：牛奶、蜂蜜、汤。
3. 地球 Online 联动后支持净化水、盐水、蒸馏水、污染水。
4. 缺水状态应影响疲劳增长、体温调节和挖掘/战斗效率。
5. HUD 警告应给解决路径，不只报数值。

## 5. 体温 / 天气 / 群系 / 维度

### 当前状态

- 下界升温，雨/水中降温。
- 体温极端给轻量负面效果。
- 暖贴、降温包、保温毯存在。

### 主要缺口

- 没有读取群系温度、昼夜、海拔、火源、盔甲/衣物。
- 水中与雨中只做固定降温，缺少“湿冷持续影响”。
- 装备体系尚未参与体温。

### 规划

1. 建立 `ThermalContext`：
   - 维度：下界、末地、主世界。
   - 群系温度。
   - 天气：雨、雪、雷暴。
   - 水中/湿身。
   - 附近热源：火、岩浆、营火、熔炉类方块。
   - 装备/衣物保温或散热。
2. 体温变化不要每 tick 大幅跳变，要有缓冲和滞后。
3. 热/冷都要先提示，再惩罚，最后才伤害。
4. 暖贴/降温包是临时缓冲，不应覆盖离开极端环境的需求。
5. 未来衣物系统应优先接入温度，而不是先做大量装饰衣服。

## 6. 疲劳 / 连续活动 / 睡眠

### 当前状态

- 步行、疾跑、游泳、攀爬、骑乘、鞘翅和飞行已按原版累计距离分别结算疲劳与连续活动负荷。
- 短暂停下不再立刻视为完全休息。
- 白天小睡不跳过时间，夜晚睡觉折算跳过时间恢复。
- 锻炼负荷和肌肉拉伤已存在。
- `/eh status text` 和图形概览页会显示当前活动与连续负荷。

### 主要缺口

- 疲劳只有一个总值，缺少短期疲劳、长期疲劳、睡眠债的分层。
- 睡眠质量不考虑床、时间、危险、环境。
- 没有与原版幻翼/睡眠统计协同。

### 规划

1. 拆成三层：
   - 即时疲劳：短时间运动、战斗、挖掘。
   - 连续活动负荷：短休不清空，影响疲劳增长倍率。
   - 睡眠债：长期不睡，恢复慢、效率低。
2. 床上休息分为：
   - 白天小睡：短恢复，不跳时间。
   - 夜晚睡眠：跳时间 + 大恢复。
   - 危险/不适环境：恢复折扣。
3. 原版幻翼机制不硬删，未来可用睡眠债解释或配置关闭。
4. 肌肉拉伤应逐步部位化：腿部拉伤影响移动，手臂拉伤影响挖掘/攻击。

## 7. 移动 / 跳跃 / 游泳 / 潜水

### 当前状态

- 原版逐 tick 移动统计由服务端每秒取增量，已区分步行、疾跑、游泳/涉水、攀爬、骑乘、鞘翅和普通飞行。
- 各移动类型使用不同的疲劳、水分、连续负荷和部位训练权重；载具不会再误算为腿部步行。
- 跳跃损耗腿部，摔落结算到腿。
- 水下额外空气可由超凡适应联动。

### 主要缺口

- 跳跃只检测起跳，没有考虑落地冲击以外的重复运动疲劳。
- 游泳、潜水、缺氧没有完整接入人体系统。
- 完全自定义且不维护原版统计的 modded 移动方式还缺少公开活动声明 API。

### 规划

1. 增加公开活动声明 API，供不维护原版统计的自定义移动方式接入。
2. 跳跃连续计数，高频跳跃增加腿部负荷和拉伤风险。
3. 缺氧应影响头部/全身，而不是只等待原版扣血。
4. 冰面、灵魂沙、水流、粉雪等特殊移动方块后续接入。

## 8. 挖掘 / 工具 / 工作强度

### 当前状态

- 挖掘会训练双臂，手臂伤势影响挖掘速度。

### 主要缺口

- 没有按工具重量/方块硬度区分工作强度。
- 没有考虑效率附魔、急迫、挖掘疲劳和真实疲劳的关系。
- 没有粉尘、噪音、震动、矿洞环境压力。

### 规划

1. 挖掘负荷由三部分决定：
   - 工具类别/重量。
   - 方块硬度。
   - 玩家状态：疲劳、手臂伤势、肌肉拉伤。
2. 保留效率附魔的爽感，但疲劳高时收益递减。
3. 石头、矿物、砂砾、泥土、木材等类别产生不同工作负荷。
4. 与地球 Online 联动后，粉尘/矿洞空气质量接入呼吸系统。

## 9. 战斗 / 盾牌 / 远程

### 当前状态

- 近战攻击训练手臂和躯干。
- 近战受击尝试按攻击者视线估算部位。

### 主要缺口

- 没有武器重量、攻击速度、盾牌格挡、弓弩拉弦、投掷物。
- 远程伤害未按命中点分配。
- 护甲只由原版处理，没有人体系统解释。

### 规划

1. 近战攻击负荷取决于武器类型和攻击频率。
2. 盾牌格挡主要消耗手臂/躯干，挡重击可能造成手臂负荷。
3. 弓弩拉弦训练手臂和躯干，疲劳高时可降低拉弓稳定性。
4. 箭、三叉戟、投掷物优先按命中位置结算。
5. 护甲先作为伤害分配前的原版减伤保留，后续加入防护部位和重量/散热。

## 10. 装备 / 护甲 / 衣物

### 当前状态

- 还没有衣物系统。
- 口罩、防尘口罩是物品，但暂未参与空气/装备槽。

### 主要缺口

- 原版护甲只有防御，没有保温、散热、负重、覆盖部位。
- 没有 Curios/饰品兼容路线。
- 没有衣物界面和换装解释。

### 规划

1. 短期先不做完整衣物槽，避免和各种装备 mod 冲突。
2. 先使用标签读取原版护甲：
   - 金属甲：重量高、散热差、防护好。
   - 皮甲：保温略好、轻。
   - 下界合金/钻石：防护强但体温/负重后续再调。
3. 口罩类先做手持/快捷使用或 Curios 可选支持。
4. 真正衣物系统可作为下一阶段重点，但要保持可配置、可兼容。

## 11. 药水 / 状态效果 / 附魔

### 当前状态

- 使用部分原版效果作为后果：虚弱、缓慢、挖掘疲劳、饥饿等。
- 肌肉拉伤已是自定义效果。

### 主要缺口

- 没有系统性映射原版药水到人体状态。
- 再生/瞬间治疗对部位血量的影响目前主要由自定义物品处理。
- 抗火、水肺、速度、力量等没有影响水分/体温/疲劳。

### 规划

1. 原版药水保留原功能，但补充人体解释：
   - 再生：缓慢治疗最严重部位。
   - 瞬间治疗：可治疗头部，但不要完全绕过身体系统。
   - 抗火：降低热伤/过热压力。
   - 水肺：降低缺氧压力。
   - 速度/跳跃提升：提高活动负荷增长，避免无代价狂奔。
   - 力量：攻击更强，但疲劳成本更高。
2. 自定义人体状态不硬塞到原版 buff，原版 buff 只做表现/兼容层。
3. 附魔后续通过 tags 或事件弱接入，避免破坏装备 mod。

## 12. 睡觉 / 床 / 重生点

### 当前状态

- 白天小睡不跳时间。
- 夜晚睡眠折算跳过时间恢复疲劳。

### 主要缺口

- 没有睡眠质量、睡眠债、床质量、危险环境、维度差异。
- 没有处理“多人服务器睡眠百分比”与个人恢复的关系。

### 规划

1. 保留原版夜晚跳过机制，不和服务器睡眠规则硬冲突。
2. 个人恢复用实际睡眠 tick + 时钟跳过量计算。
3. 增加睡眠债，但默认只影响恢复速度和疲劳上限，不直接杀人。
4. 下界/末地床爆炸不改，除非未来加入睡袋/营地系统。

## 13. 环境方块 / 方块接触

### 当前状态

- 水、雨、下界已轻量接入。
- 仙人掌、浆果、火、岩浆、冻伤等只在伤害类型里粗略处理。

### 主要缺口

- 原版大量环境方块没有人体解释：粉雪、岩浆、营火、灵魂营火、蜂巢、荆棘、甜浆果、细雪、水流、冰、脚手架、梯子。

### 规划

1. 先做伤害型方块映射。
2. 再做环境型方块影响：
   - 粉雪/冰水：体温下降。
   - 营火/火把/岩浆附近：升温或保暖。
   - 甜浆果/仙人掌：腿部/手臂划伤。
   - 梯子/脚手架：手臂/腿部负荷。
3. 所有环境影响都应可配置倍率。

## 14. 空气质量 / 粉尘 / 烟雾

### 当前状态

- 口罩物品存在，但系统未实现。

### 主要缺口

- 原版没有空气质量，地球 Online 工业体系也需要这个接口。
- 矿洞粉尘、烟雾、下界空气、有毒气体未接入。

### 规划

1. 建立轻量 `AirQualityContext`：
   - 水下/缺氧。
   - 烟雾源：营火、火焰、熔炉/工业设备联动。
   - 粉尘源：挖矿、砂砾、地球 Online 粉体加工。
   - 维度基础空气。
2. 口罩降低粉尘，不解决缺氧。
3. 防毒面具/呼吸器留给后续装备层。
4. 默认只提示和轻惩罚，不做无提示暴毙。

## 15. 配置 / 难度 / 兼容

### 当前状态

- 还没有正式配置系统和难度预设。

### 主要缺口

- 现在数值全硬编码，调试和整合包适配很痛。
- 用户很难关闭某个不喜欢的系统。

### 规划

1. v0.2 必须加入配置：
   - enableHydration
   - enableTemperature
   - enableFatigue
   - enableBodyHealth
   - enableTraining
   - enableAirQuality
   - globalDifficultyMultiplier
2. 预设：
   - casual：轻量提示，低惩罚。
   - standard：默认。
   - realistic：更真实但仍可玩。
   - pack_author：整合包作者手调。
3. 所有核心倍率配置化：水分、体温、疲劳、治疗、训练、伤害扩散。

## 16. UI / 手册 / 新手教学

### 当前状态

- 有 HUD、身体小人、命令帮助。
- 野外健康记录已经可以打开图形化状态面板，含概览、身体、护理和显示设置。
- 快捷护理已经支持服务端校验、动作耗时、物品消耗和公开兼容标签。

### 主要缺口

- 玩家不知道第一步该做什么。
- 缺少图形化手册页。
- 命令帮助太像调试，不像新手教程。

### 规划

1. 继续扩展 `field_health_note` 图形界面，加入训练、连续活动负荷和更完整的新手页。
2. 手册第一页必须回答：
   - 我现在多了什么系统？
   - 红心为什么变少？
   - 我口渴/累/受伤怎么办？
   - 白天怎么休息？
   - 该带哪些基础物品？
3. 加入“新手 5 件套”配方/提示：水壶、绷带、恢复茶、训练垫、口罩。
4. HUD 高级数值可开关，默认只显示玩家能懂的提示。

## 17. 下一阶段执行顺序

## 18. 不建议现在做

- 复杂营养素 UI。
- 食物腐败。
- 硬核疾病随机触发。
- 心理健康。
- 社会系统。
- 完整衣物换装系统。

这些可以做，但不应该在当前测试版核心闭环还没打稳时抢优先级。
