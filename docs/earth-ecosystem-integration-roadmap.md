# 地球系列四 Mod 联动路线图

日期：2026-07-16
目标平台：Minecraft 26.2 / NeoForge 26.2.0.7-beta

## 1. 定位

四个 Mod 是可以任意选择安装的独立产品，不是互相拆散后不再联动的孤岛：

| Mod | 核心职责 | 不应承担 |
|---|---|---|
| Earth on Minecraft | 现实材料、地质、矿床、工业、电力、物流和基础设施 | 人体难度、修炼体系、魔法规则 |
| 地球：人类 | 人体状态、活动、伤害、治疗、环境压力和生活系统 | 现实工业全流程、灵气场、魔法场 |
| 地球 Online：玄幻 | 灵气场、修炼、功法、丹药、符箓、阵法 | 直接实现人体底层或复制现实工业 |
| Earth Online: Magic | 以太场、调律、炼金、符文、仪式、结界 | 直接实现人体底层或复制现实工业 |

联动原则：

1. 任意一个 Mod 单独安装都必须能启动并形成自己的基础玩法。
2. 联动是增强路线，不是基础启动条件。
3. 数据标签优先于硬编码物品 ID，公开 API 优先于直接读写其他 Mod 私有数据。
4. 每个持久数据键必须有唯一所有者；其他 Mod 只能通过公开契约读取或请求修改。
5. 不增加第五个玩家必装的“公共前置”。共享规范可以作为开发期文档、测试向量或构建资源存在。
6. 玩家界面只解释“装了什么、增加了什么、下一步怎么做”，不暴露内部 API、NBT 或兼容实现。

## 2. 当前基线

实际测试实例当前启用：

| Mod | 部署版 | 工作树状态 |
|---|---:|---|
| Earth on Minecraft | 0.1.9 | 实际工作树远超 Git HEAD 0.1.6，含大量资源和地质改动 |
| 地球：人类 | 0.1.18 | `EarthHumanApi v1`、三类身体摘要、空气质量/PPE 和入门手册已实现并通过测试 |
| 地球 Online：玄幻 | 0.4.1 | 实际工作树远超 Git HEAD 0.1.1 |
| Earth Online: Magic | 0.4.1 | 实际工作树远超 Git HEAD 0.1.1 |

已确认可用的联动：

- 玄幻配方实际消费 `arcana_geology_catalysts`、`spiritual_mineral_substrates` 和 `mana_conductors`。
- 魔幻配方实际消费 `arcana_geology_catalysts`、`aether_crystal_substrates` 和 `mana_conductors`。
- 两个附属都声明 Earth on Minecraft 与地球：人类为可选依赖，并在其后加载。
- 玄幻与魔幻使用同一条 `earth_online_arcana.current_mana` 法力值，路线贡献相加。
- 地球：人类会读取超凡适应数据，为疲劳、水分、体温、空气和食物消耗提供轻量联动。

当前缺口：

- 两个附属原先的 `EarthHumanCompat` 会直接修改 `earth_human.*` 私有 NBT 并写死旧部位上限；0.1.15 / 0.4.2 已迁移到公开 API，这一风险已收口。
- 两个 `ArcanaPower` 复制了共享法力公式。当前基本公式一致，但没有契约版本和一致性测试，后续容易分叉。
- `endurance_bonus`、`breath_capacity_bonus`、`body_tempering_bonus` 等键由多条路线共同累加，没有明确的单一所有者和重算规则。
- Earth on Minecraft 已定义 `human_adaptation_inputs`，但地球：人类和两个附属尚未实际消费。
- 玄幻灵气场和魔幻以太场当前主要扫描自身方块；现实矿床、岩性、电力和化工环境尚未真正影响场值。
- 三个旧仓库的 Git 基线落后于部署版。继续跨仓库修改前必须先建立可复现提交，避免发布、回滚和问题定位失真。

## 3. 稳定契约

### 3.1 地球：人类公开 API

`earth_human.*` 数据只由地球：人类拥有。其他 Mod 不得再直接写入以下内容：

- 疲劳、水分、体温和连续活动负荷。
- 身体初始化版本、部位血量、部位上限和迁移标记。
- 护理动作、同步时间和客户端状态。

第一版公开入口应提供：

- `apiVersion()`：返回兼容 API 版本。
- `snapshot(player)`：返回疲劳、体温、水分、头部完整度和全身完整度的只读快照。
- `recover(player, request)`：由服务端按当前配置降低疲劳、治疗指定部位并同步。
- `applyActivity(player, request)`：供自定义坐骑、飞行、锻炼或法术动作申报活动负荷，后续实现。
- 伤害与治疗事件：供其他 Mod 在分配前后附加语义，后续实现。

两个附属保持对地球：人类的可选依赖。第一阶段可通过一次解析并缓存的反射适配器调用公开 API；API 不存在时联动安全失效，不再回退到写私有 NBT。

### 3.2 共享法力契约

暂不增加运行时公共 Mod。共享法力采用“版本化规范 + 两侧一致性测试”管理。

共享核心键：

| 键 | 所有权 | 规则 |
|---|---|---|
| `earth_online_arcana.contract_version` | 共享契约 | 只允许向前迁移 |
| `current_mana` | 共享契约 | 两侧通过相同钳制公式修改 |
| `base_mana` | 共享契约 | 默认 20，存档值非负 |
| `xuanhuan_mana_bonus` | 玄幻 | 魔幻只读 |
| `magic_mana_bonus` | 魔幻 | 玄幻只读 |
| `equipment_mana_bonus` | 待迁移 | 不允许多个 Mod 继续覆盖同一总值 |
| `temporary_mana_bonus` | 待迁移 | 改为带来源和到期时间的贡献集合 |

路线私有键：

- 玄幻拥有 `qi_absorption_rate`、`cultivation_level`、`bigu_level`、`body_tempering_level`、`fetal_breath_level`、玄幻焦点、冷却和最后动作。
- 魔幻拥有 `magic_attunement_rate`、`magic_research_level`、护体/呼吸结界等级、魔幻焦点、冷却和最后动作。

多来源适应值应从“共同累加一个总键”迁移为“按来源保存、读取时求和”：

```text
earth_online_arcana.contribution.xuanhuan.endurance
earth_online_arcana.contribution.magic.endurance
earth_online_arcana.contribution.xuanhuan.breath_capacity
earth_online_arcana.contribution.magic.breath_capacity
earth_online_arcana.contribution.xuanhuan.body_tempering
earth_online_arcana.contribution.magic.body_tempering
```

迁移必须幂等：记录迁移版本，旧总值只读取一次，不能因重启、死亡克隆或重新学习重复叠加。

### 3.3 Earth on Minecraft 数据出口

现有物品标签继续作为稳定材料角色，而不是让附属依赖具体物品：

| 标签 | 当前消费者 | 下一步 |
|---|---|---|
| `arcana_geology_catalysts` | 玄幻、魔幻 | 保持 |
| `spiritual_mineral_substrates` | 玄幻 | 保持并增加高级丹材路线 |
| `aether_crystal_substrates` | 魔幻 | 保持并增加晶体/仪式路线 |
| `mana_conductors` | 玄幻、魔幻 | 用于阵法、符文和法力设备，不硬编码铜线 |
| `human_adaptation_inputs` | 尚无 | 接入净水、补液、过滤和呼吸防护路线 |
| `chemical_products` | 尚无直接附属消费 | 继续拆分更具体的酸、碱、盐、溶剂、气体角色标签 |
| `concentrates` / `mineral_chunks` / `mineral_dusts` | 本体 | 供附属按需要选择角色，不整包当作神秘材料 |

地质联动不能依赖全区块高频扫描。分两步实现：

1. 先提供稳定 block tags，例如含硅岩性、含汞矿物、稀土矿物、磁性矿物、导电矿物、灵性候选矿床。
2. 再提供只读 `GeologyQueryApi`，返回当前位置的主要岩性、已知矿床角色、温度/湿度和工业环境摘要；无本体时附属继续使用自身自然背景值。

### 3.4 玩家可见联动

每个 Mod 的手册增加“已安装联动”页，但只描述自己获得的增强：

- Earth on Minecraft：说明哪些材料可进入人体、玄幻和魔幻路线。
- 地球：人类：说明工业补给、修炼适应和魔法防护对人体有什么效果。
- 玄幻：显示现实材料路线、人体恢复是否可用、魔幻路线对共享法力的贡献。
- 魔幻：显示现实材料路线、人体恢复是否可用、玄幻路线对共享法力的贡献。

缺少某个 Mod 时显示“可选增强未安装”，不得显示报错，也不得把它写成必装步骤。

## 4. 分阶段实施

### 阶段 0：建立可复现基线

目标：先把实际部署内容变成可追踪版本。

1. 分别审查 Earth on Minecraft、玄幻和魔幻的未提交改动。
2. 清除构建缓存、临时图片和备份文件等不应入库内容，但不回退现有功能改动。
3. 运行各自资源校验、构建和专服启动。
4. 以当前部署版建立 Git 提交和测试版 tag。

验收：Git HEAD、README 版本、mods metadata、jar 文件名和实例活动 jar 一致。

### 阶段 1：人体 API 收口（已完成）

目标版本建议：地球：人类 0.1.18，玄幻/魔幻 0.4.2。

1. 地球：人类已增加稳定 API 版本、人体快照和服务端恢复请求。
2. API 已使用当前真实部位上限、配置倍率、模型迁移、保存和网络同步。
3. 玄幻与魔幻的 `EarthHumanCompat` 已改为调用 API。
4. 已删除写死的 10/16/10/12 上限和所有 `earth_human.*` 写操作。
5. 纯 Java 契约测试已覆盖 API 版本和部位 ID 解析；四 Mod 组合专服已通过启动验证。

验收：额外最大生命下治疗比例正确；死亡、重登和升级旧存档后状态不损坏；两个附属单独安装仍能运行。

### 阶段 2：共享法力契约 v2

目标版本建议：玄幻/魔幻 0.4.3。

1. 增加 `contract_version` 和幂等迁移。
2. 拆分玄幻/魔幻的耐力、呼吸和锻体贡献。
3. 把共享公式抽成相同测试向量，两仓库 CI 都必须通过。
4. 明确死亡克隆、维度切换、卸载其中一个附属和重新安装时的规则。
5. 当前法力超过新上限时只钳制一次，不删除另一条路线的数据。

验收：只装玄幻、只装魔幻、两者同装、先后卸载/重装四种存档流程结果一致。

### 阶段 3：现实地质与场联动

目标版本建议：Earth on Minecraft 0.1.10，玄幻/魔幻 0.5.0。

1. Earth on Minecraft 发布地质角色 block tags。
2. 玄幻灵气场读取灵性候选矿床、含水地层和特定岩性，使用有界扫描与缓存。
3. 魔幻以太场读取晶体基质、导电/磁性材料和现实能源设施，但保持与灵气场不同权重。
4. 后续再用 `GeologyQueryApi` 替代重复扫描。

验收：同一现实矿床对两个场产生不同且可解释的影响；未安装本体时场系统保持原有基线。

### 阶段 4：工业与人体联动

1. `human_adaptation_inputs` 接入补液盐、净水、过滤材料和呼吸防护配方。
2. Earth on Minecraft 只提供材料和环境事实；人体效果由地球：人类服务端 API 决定。
3. 为粉尘、腐蚀、热、缺氧等工业环境预留事件，不在默认模式制造突发高难度。
4. PPE、过滤、净水和急救路线必须有 JEI 与手册新手路径。

验收：不装地球：人类时工业本体不产生人体报错；装上后才出现可理解的附加效果。

### 阶段 5：跨 Mod 手册与 JEI

1. 四个手册动态显示安装状态和有效联动。
2. JEI 只展示当前安装组合可完成的配方。
3. 所有联动页面提供“第一步”“为什么需要”“下一步去哪”三段信息。
4. 不把四本手册合并为一个强制核心；各 Mod 仍拥有自己的知识边界。

### 阶段 6：完整交叉玩法

- 现实矿物/化工材料 -> 丹药、阵法、符文和仪式的高产或高级路线。
- 修炼/魔法 -> 人体恢复、呼吸、耐力和环境适应，但不直接绕过人体规则。
- 电力/自动化 -> 可选驱动大型阵法或仪式控制设备，法力和 EOU 不互相冒充。
- 人体状态 -> 影响修炼/调律效率和反馈，不把默认玩法变成硬核生存惩罚。

## 5. 安装组合测试矩阵

四个 Mod 共有 15 种非空安装组合。发布前自动执行全部组合的专服启动冒烟测试，并对以下组合做重点客户端玩法验证：

1. 四个 Mod 各自单独安装。
2. Earth on Minecraft + 玄幻。
3. Earth on Minecraft + 魔幻。
4. Earth on Minecraft + 地球：人类。
5. 地球：人类 + 玄幻。
6. 地球：人类 + 魔幻。
7. 玄幻 + 魔幻。
8. 四个全部安装。

每个组合至少验证：

- 加载阶段无缺失类、注册表、数据包和可选依赖错误。
- 新建世界、进入世界、死亡克隆、退出重进正常。
- 手册和 JEI 不引用缺失物品。
- 共享法力和人体状态不会因安装顺序、卸载或重装被清空或重复叠加。
- 实例中每个 Mod 只保留一个活动 jar，旧 jar 只能使用非 `.jar` 备份扩展名。

## 6. 紧接着实施的切片

人体 API 切片已经完成。下一轮按以下顺序直接执行：

1. 为两个 `ArcanaPower` 建立共享法力一致性测试与键所有权清单。
2. 增加 `contract_version`，拆分玄幻/魔幻共同写入的适应贡献键。
3. 实现幂等旧存档迁移，并覆盖死亡、卸载一个附属、重新安装的测试向量。
4. 再进入 Earth on Minecraft 地质角色 block tags 与场域联动。
5. 四个手册动态展示有效联动和缺失增强，但继续保持各自独立。

当前四 Mod 已具备继续交叉扩展的基础；共享法力多写方仍是下一项必须先收口的风险。
